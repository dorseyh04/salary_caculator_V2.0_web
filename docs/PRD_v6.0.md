# 业务人员月度薪酬核算 — App 开发完整提示词（v6.0）

> 本文档定义薪酬核算 App 的完整业务逻辑、数据结构和交互要求。
> 修改规则时直接编辑对应章节，保持格式不变。

---

## 一、系统概述

### 1.1 角色
薪酬核算系统负责业务人员月度薪酬的自动核算，严格按规则计算，不得自行推断或编造数据。

### 1.2 月度薪酬结构（制度依据：第三条、第四条）

```
月度薪酬 = 基本工资 + 绩效工资 + 销售提成 + 溢价提成 + 贸易业务提成
```

> 年度奖金、文化工资、相关补贴不在本 App 核算范围内。

### 1.3 输入

用户需上传 **1 份回款明细 Excel**（含 2 个 Sheet）和 **1 份绩效分 Excel**，并在 App 界面上**手动录入/修改**部分参数。

| 输入项 | 方式 |
|--------|------|
| 《回款明细》（Sheet1：回款明细） | 上传 Excel |
| 《回款明细》（Sheet2：基价表） | 同一文件，App 自动读取（如该 Sheet 存在） |
| 《x 月绩效分》 | 上传 Excel |
| 基本工资 | App 界面手动输入（默认从绩效分表读取，可逐人修改） |
| 绩效工资基数 | App 界面手动输入（默认从绩效分表读取，可逐人修改） |
| 当月抵扣项目总额 | App 界面手动录入（逐人输入，默认为 0） |
| 居间费（溢价提成扣除项） | **从回款明细 AA 列逐行自动读取**（>0 才参与溢价修正），无需手工录入 |
| 负毛利订单 | **从回款明细 Z 列自动识别**（含"负毛利"标记的行），无需手工录入 |
| 贸易业务毛利 | App 界面手动录入（输入订单编号 + 毛利金额 + 品类） |

## 二、文件字段定义

### 2.1 《回款明细》—— Sheet1：回款明细（25 列）

| 列 | 字段名 | 用途 |
|----|--------|------|
| A | 年 | 年份 |
| B | 月 | 月份 |

| M | 含税单价 | 含税销售单价（元） |
| **N** | **含税金额** | **订单总额，当前系统用于计算出厂售价与提成基数** |

| P | 交易日期 | 实际交易日期 |

| U | 业务经理 | 业务人员姓名 |
| **V** | **基价** | **产品基价（元/kg）**，部分行为直接数值，部分行为 VLOOKUP 公式引用基价表 |
| **W** | **运费单价** | **运费单价（元/kg），直接读同行，已含税** |
| **X** | **提成活跃度系数** | **该笔订单对应客户的提成活跃度系数**，直接读同行数值；为空时 App 默认取 1 |
| **Y** | **分类** | **产品线分类**（普通个体防护、高端个体防护、工业吸附、液滤、空滤、生活擦拭、耐高温材料、透气弹性材料、贸易、副牌等），**决定销售提成系数**；Y 列为空时回退读 T 列「类别」 |
| **Z** | **负毛利** | **负毛利标记列**：含"负毛利"字样的行，销售提成系数统一按 0.25% 计算（覆盖产品线系数）；空白行为常规订单 |
| **AA** | **居间费** | **居间费单价（元/kg），逐行读取**：数值 >0 时作为该行的溢价提成扣除项参与计算；为 0 或空白则不参与 |

### 2.2 《回款明细》—— Sheet2：基价表（6 列）

> App 需读取此表，用于解析 V 列中的 VLOOKUP 公式。

| 列 | 字段名 | 说明 |
|----|--------|------|
| A | 物料编码 | 产品编码（与 Sheet1 的 I 列匹配） |
| B | 部门 | 部门名称 |
| C | 产品大类 | 产品分类 |
| D | 品名 | 产品名称 |
| E | 切边率 | 切边率 |
| F | 当月基价 | 该物料的基价（元/kg） |

### 2.3 基价读取逻辑

V 列基价的读取分两种情况：
1. **V 列为直接数值** → 直接使用
2. **V 列为 VLOOKUP 公式或为空** → App 用 I 列（物料编码）匹配基价表 Sheet 的 A 列，取 F 列的基价值

> 若两种方式均无法获取基价 → 跳过该笔，计入异常预警。

### 2.4 《x 月绩效分》（5 列）

> 第 1 行为月份标题（如"6月 绩效汇总"），第 2 行为列头，第 3 行起为数据。绩效工资统计的数据和项目以上传附件为准。

| 列 | 字段名 | 说明 |
|----|--------|------|
| A | 姓名 | 业务人员 |
| B | 当月绩效分 | 取值 0~1 |
| C | 基本工资标准 | 默认值，可由用户在 App 界面覆盖 |
| D | 绩效等级 | 一级 / 二级 / 三级 |
| E | 绩效工资基数 | 默认值（一级=2000，二级=3000，三级=4000），可由用户在 App 界面覆盖 |

> **注意**：绩效分表中**不含**"当月抵扣项目总额"。抵扣项目总额需在 App 界面中逐人手动录入。

## 五、数据清洗规则

### 5.1 无效回款过滤（第一步）

| 条件 | 判断 | 处理 |
|------|------|------|
| 物料编码为空 | I 列为空 | 剔除，不参与提成 |
| 预收款/无合同 | R 列含"预收款"或"无合同" | 剔除，不参与提成 |

> 被剔除记录的收款金额仍计入交叉验证的"全部收款"。

### 5.2 贸易业务分流（第二步）

| 条件 | 判断 | 处理 |
|------|------|------|
| 分类为"贸易" | 分类字段 = 贸易 | 从常规提成计算中剔除，进入贸易业务提成流程（第六章第 6.5 节） |

> 贸易订单的收款金额仍计入交叉验证的"全部收款"和"有效收款"，但标注为"贸易业务-单独核算"。

### 5.3 数量单位换算（统一为 kg，记为"核定公斤"）

> 基价和运费单价单位均为元/kg，必须先统一数量口径。

| 情况 | 处理 |
|------|------|
| K 列为 `kg` 或 `公斤` | 核定公斤 = L 列数量 |
| K 列为 `箱`、`包`、`个`、`卷` 等 | 从 J 列提取重量，核定公斤 = L列数量 × 单件重量 |

- 提取正则：`(\d+\.?\d*)\s*[Kk][Gg]`
- 常见格式：`_4KG/箱`、`_5KG/包`、`_0.32KG/个`
- 无法提取 → 跳过该笔，计入异常预警

### 5.4 基价读取

按 2.3 节逻辑读取。优先读 V 列直接数值，其次用 I 列匹配基价表 F 列。均无法获取 → 跳过该笔，预警。

### 5.5 运费单价读取

**直接读同行 W 列（运费单价，元/kg，已含税）。**

- W 列为空或 0 → 运费单价 = 0，正常计算。

**该笔运费总额** = 运费单价（W 列） × 核定公斤

### 5.6 产品线提成系数匹配

根据回款明细“分类”列匹配销售提成系数（见第三章 3.2 节）：

| 分类取值 | 匹配的销售提成系数 |
|---------|-----------------|
| 普通个体防护 | 0.5% |
| 高端个体防护 | 0.7% |
| 工业吸附 | 0.5% |
| 液滤 / 液滤-电驻极 | 0.5% |
| 空滤 | 0.5% |
| 生活擦拭 | 0.6% |
| 耐高温材料 | 0.8% |
| 透气弹性材料 | 1% |
| 副牌 | 按所属产品大类匹配，无法判断时取 0.5% 并预警 |
| 贸易 | 不参与销售提成（走贸易流程） |

> 若分类列出现未列入的新分类 → 预警提示，暂按 0.5% 计算。

### 5.7 提成活跃度系数读取

直接读同行 X 列。为空时默认取 **1**。

## 六、薪酬计算规则

### 6.1 基本工资（制度依据：第四条（一））

用户在 App 界面设置的值优先；否则从绩效分表 C 列读取。默认全员 2000 元/月。

### 6.2 绩效工资（制度依据：第四条（二））

```
月度绩效工资 = 绩效工资基数 × 当月绩效分
```

| 参数 | 来源 | 特殊处理 |
|------|------|---------|
| 当月绩效分 | 绩效分表 B 列 | 取值 0~1 |
| 绩效工资基数 | 用户 App 界面值优先，否则绩效分表 E 列 | 按绩效等级：一级=2000，二级=3000，三级=4000 |

> **注意**：绩效工资基数与基本工资是**两个独立参数**，可分别设置。
> 绩效工资统计的数据和项目以上传的绩效分附件为准。

### 6.3 销售提成（制度依据：第四条（三））

> 制度逻辑：销售提成激励"基价以内"的回款部分，按产品线差异化提成系数，并乘以提成活跃度系数。
> **贸易订单（分类="贸易"）不参与销售提成计算。**

#### 逐笔订单计算（以收款金额为准）

**步骤 1 — 计算出厂售价**
```
出厂售价 = （收款金额 - 运费单价 × 核定公斤） ÷ 核定公斤
```
> 出厂售价的含义：从收款金额中剔除运费后，每公斤的实际含税出厂净单价。

**步骤 2 — 判断该笔销售提成基数**
```
若 出厂售价 > 基价  → 该笔销售提成基数 = 基价 × 核定公斤
若 出厂售价 ≤ 基价 → 该笔销售提成基数 = 出厂售价 × 核定公斤（即：收款金额 - 运费总额）
```

**步骤 3 — 确定该笔提成系数和活跃度系数**
```
该笔提成系数：
  负毛利订单（用户在界面标注的订单编号） → 0.25%（覆盖产品线系数）
  常规订单 → 按回款明细“分类”列查表（见第三章 3.2 节）

该笔活跃度系数：
  读取 X 列，为空默认 1
```

**步骤 4 — 计算该笔销售提成**
```
该笔销售提成 = 该笔销售提成基数 × 该笔提成系数 × 该笔活跃度系数
```

**步骤 5 — 汇总**
```
销售提成 = Σ 全部有效订单的逐笔销售提成 - 当月抵扣项目总额 × 该人加权平均提成系数
```

> **抵扣项目扣除方式说明**：
> 当月抵扣项目总额来自用户在 App 界面的录入。
> 加权平均提成系数 = 该人全部逐笔销售提成之和 ÷ 该人全部逐笔销售提成基数之和。
> 即：抵扣项目按该人当月实际的加权提成水平来扣除。

| 参数 | 说明 |
|------|------|
| 当月抵扣项目总额 | 用户在 App 界面逐人录入（含运输费、差旅费、招待费、样品费） |
| 产品线提成系数 | 按“分类”列匹配（0.5%~1%），见 3.2 节 |
| 负毛利提成系数 | **0.25%**（覆盖产品线系数） |
| 提成活跃度系数 | 按 X 列读取（1~0.5），见 3.3 节 |

> 若计算结果为负数，销售提成取 0。

### 6.4 溢价提成（制度依据：第四条（四））

> 制度逻辑：溢价提成激励"超出基价"的溢价部分。部分客户有居间费用，需先修正出厂售价。
> **贸易订单（分类="贸易"）不参与溢价提成计算。**
> **提成活跃度系数不适用于溢价提成。**

#### 逐笔订单计算

**步骤 1 — 确定居间费**
- 读取该笔订单行的 **AA 列（居间费）**
- 若 AA 列数值 > 0 → 居间费 = 该数值（元/kg）
- 若 AA 列为 0 或空白 → 居间费 = 0（不参与溢价修正）

**步骤 2 — 计算溢价修正单价**
```
溢价修正单价 = 出厂售价 - 居间费
```
> 出厂售价为销售提成计算中已算出的值（第 6.3 节步骤 1）。

**步骤 3 — 判断并计算溢价提成**
```
若 溢价修正单价 > 基价：
  溢价提成基数 = （溢价修正单价 - 基价） × 核定公斤
  溢价率 = 溢价修正单价 ÷ 基价 - 1
  根据溢价率查表获取溢价提成系数（见第三章 3.4 节系数表）
  该笔溢价提成 = 溢价提成基数 × 溢价提成系数

若 溢价修正单价 ≤ 基价：
  该笔溢价提成 = 0
```

**步骤 4 — 汇总**
```
当月溢价提成 = 全部有效订单的溢价提成之和
```

### 6.5 贸易业务提成（制度依据：第四条（五））

> 贸易业务不列入常规业绩基数，按单核算毛利后单独计入当月薪酬。

#### 识别规则
分类 = "贸易" 的订单自动识别为贸易业务。

#### 计算方式
```
该笔贸易提成 = 该笔毛利金额 × 对应品类提成比例
```

| 贸易品类 | 提成比例 |
|---------|---------|
| 熔喷料 | **40%** |
| 母粒 | **30%** |
| 无纺布 | **20%** |

> 毛利金额和品类由用户在 App 界面手动录入（第四章步骤 2e），App 不自动计算贸易毛利。

#### 汇总
```
当月贸易业务提成 = Σ 每笔贸易订单的贸易提成
```

### 6.6 月度薪酬合计

```
月度薪酬 = 基本工资 + 绩效工资 + 销售提成 + 溢价提成 + 贸易业务提成
```

## 八、异常预警

| 异常类型 | 触发条件 | 处理 |
|---------|---------|------|
| 基价缺失 | V 列为空/公式且基价表无匹配 | 跳过该笔提成 |
| 单位折算失败 | 非 kg 且描述中无重量参数 | 跳过该笔 |
| 运费单价缺失 | W 列为空 | 运费单价=0，正常计算 |
| 收款≠含税 | O 列 ≠ N 列 | 正常按 O 列计算，标注差额 |
| 居间费生效提示 | 回款明细 AA 列居间费 >0 的行 | 在相关订单中标注已应用居间费扣除 |
| 负毛利订单提示 | 回款明细 Z 列含"负毛利"标记的行 | 在相关订单中标注已应用 0.25% 提成系数 |
| 贸易订单无毛利 | 分类="贸易"但用户未录入毛利金额 | 预警提示，该笔贸易提成按 0 计算 |
| 未知产品线分类 | 分类值不在已知分类列表中 | 预警提示，暂按 0.5% 计算 |
| 活跃度系数异常 | X 列值不在 [0.5, 0.6, 0.7, 0.8, 1] 范围内 | 预警提示，按原值计算 |
| 副牌归类提示 | 分类="副牌"的订单 | 标注已按最低档 0.5% 计算（或按判断出的所属大类计算） |

## 十、补充规则

1. **人员范围**：以《x 月绩效分》人员名单为准。回款明细中出现但绩效分表中没有的人员，其订单数据正常参与交叉验证但不计算薪酬，并在异常预警中提示。
2. **基本工资与绩效工资基数独立**：两者可分别设置，互不联动。
3. **居间费按订单行读取**：居间费从回款明细 AA 列逐行读取（元/kg），仅影响溢价提成计算，不影响销售提成计算。AA 列为 0 或空白的行不参与溢价修正。不再使用按售达方手工录入与浏览器本地存储的方式。
4. **运费单价直接读取**：回款明细 W 列已包含运费单价（元/kg，已含税），无需单独上传运费表。
5. **负毛利订单**：从回款明细 Z 列自动识别，含"负毛利"标记的行销售提成系数统一按 **0.25%** 计算，覆盖产品线系数。负毛利标记仅影响销售提成系数，不影响溢价提成。
6. **贸易业务独立核算**：分类="贸易"的订单不参与常规销售提成和溢价提成，按毛利 × 品类提成比例单独核算。
7. **基价解析**：优先读 V 列数值，V 列为公式或空时用 I 列匹配基价表。在逐笔明细中标注基价来源。
8. **提成活跃度系数**：仅适用于销售提成，溢价提成不适用。从 X 列读取，为空默认 1。
9. **数据精度**：中间保留完整精度，最终两位小数。
10. **核算月份**：以《回款明细》S 列确定。
11. **同一订单可含多行**：每行独立计算。
12. **当月绩效分直接从绩效分表 B 列读取**，绩效工资按绩效工资基数乘以当月绩效分计算。
13. **副牌处理**：分类为"副牌"的订单参与常规提成计算，提成系数按最低档 0.5% 计算并预警。
14. **制度执行日期**：本方案自 2026 年 5 月 1 日起执行。
